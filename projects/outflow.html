PROJECT 03 / AI AGENT

Outflow — 对话式支出管理 Agent

把票据与随手记录转化为结构化账本，并用可追溯的工具调用回答支出问题。

项目问题

记录要足够轻，答案要足够可信

传统预算工具往往要求用户手动录入大量字段，记录成本高；数据进入表格后，用户仍需要自行筛选和计算。Outflow 面向有固定月度预算的学生，聚焦两个结果：用票据或一句自然语言快速记录支出，并用自然语言直接查询可信数字。

设计原则

AI 处理模糊性，确定性工具处理精确性

生成式模型只放在输入和输出两端：负责把不同格式的票据、图片或随手记录转换成结构，并理解用户的自然语言问题。分类、日期解析、数学计算和图表生成则交给可审计的规则与工具。

AI / INPUT票据真实性判断与信息抽取

Qwen2.5-VL-72B 输出严格 JSON；无法确定的字段返回 null。

HUMAN GATE保存前人工确认

所有数据均经过可编辑复核；被标记的票据必须显式确认后才能保存。

DETERMINISTIC分类、日期与计算

查表完成类别映射，规则解析相对日期，Calculator 负责所有总和与平均值。

AI / OUTPUT基于账本生成回答

DeepSeek V3.2 仅使用检索到的交易数据组织自然语言答案。

系统流程

从原始输入到可追溯答案

Receipt / Text→Receipt Triage→Vision Extraction→Human Review→Rule-based Category→Ledger→Retrieval + Tools→Grounded Answer

查询和月度总结共用同一套检索与工具链；图表由 pandas / matplotlib 直接从账本生成，不由大模型绘制或估算。

成功标准

在实现前固定可衡量目标

≥ 90%日期、商户与金额可正确抽取，或一次编辑内纠正
028 个完整系统测试中不允许出现无法追溯的数字
< 30s包含人工确认的单笔支出入账目标

这些是项目在实现前设定的成功标准，而不是把单次演示结果包装成指标。

原型验证

界面原型与可运行后端并行验证

产品包含 ADD、CATEGORY、ASK、SUMMARY 四个交互区域；功能后端通过 OpenRouter 调用视觉与文本模型，并连接真实账本、计算工具、规则检索、成本追踪与评测框架。

  • 69 条交易记录用于检索与查询验证
  • 28 个测试样本覆盖抽取、查询与总结
  • 3 个系统变体用于验证工具调用和检索等架构选择
